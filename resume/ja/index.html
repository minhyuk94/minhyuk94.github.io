仕事で大切にしていること

01

コミュニケーション

開発も一人で進めるものではありません。企画や営業との継続的なコミュニケーションが欠かせず、中でも企画や修正依頼が「なぜ」出てきたのか、その意図と目的を正確に把握することが最も重要だと考えています。言われた通りではなく、目的に合ったものをつくってこそ、本当に必要な結果につながります。

02

つながり

自分の担当範囲だけでなく、つながっている周辺のプロジェクトやサービス、さらには外部のサービスまで視野に入れます。「このサービスは自分たちとここが違う」「最近こんなセキュリティ問題があったが、うちも該当しないか」のように、つながりから学び、先回りして備えることを大切にしています。

03

改善への意欲

私の考える「発展」とは、新しい機能を足すことではなく、既存のサービスを改善して実際に良くなった結果を生み出すことです。改善によって収益を上げる、UI・UX を整えてユーザーが使いやすくなる、業務フローを自動化して仕事の効率を高める。こうした結果につながる改善を常に考えています。

WebCompiler

ブラウザでコンパイル・実行・採点・デバッグができるコーディングツール

つくった理由 C++ や Java でコーディングテストを練習するたびに、言語ごとのコンパイルコマンドやビルドスクリプトを用意し、デバッグ用の出力文を入れては消す作業が手間でした。コードを書くだけですぐ結果を確認でき、さらにブラウザ上でステップ実行までできるようにつくりました。

  • C・C++・Java・Python・JavaScript・PHP・Go の 7 言語を一つの画面でコンパイル・実行
  • コンパイルエラーは行番号付きで、実行時エラー（セグメンテーション違反・例外・時間／メモリ超過）は原因の説明付きで表示
  • テストケースの一括採点と、期待出力・実際の出力の行単位比較
  • C・C++・Python のステップ実行デバッガ（ブレークポイント、1 行ずつ実行、変数・コールスタック・ウォッチ式）
  • ユーザーのコードは権限のないアカウント・リソース制限・ネットワーク遮断の環境で隔離して実行

ユーチュージャム

落ちてくるノーツをリズムに合わせて叩くWebの鍵盤リズムゲーム。オリジナル曲はブラウザでリアルタイムに合成し、YouTube動画の音楽でも遊べる。PCとスマートフォンの両方に対応

つくった理由 昔のオンラインリズムゲームの手応えを、YouTubeにある好きな音楽でも楽しみたいと思って作りました。YouTubeの音声は解析できないため、テンポを合わせて譜面を作るか、自分で叩いて録音する方式で解決しました。

  • 4・5・6・7鍵とかんたん・ふつう・むずかしい、曲ごとにノーツ数から算出する難易度（Lv）
  • オリジナル4曲をWeb Audioでリアルタイム合成し、ノーツを曲の音から作って叩いた瞬間にその音が鳴るキー音方式
  • スピーカー出力時刻に合わせた時計とキー入力時刻そのままの判定、ロングノーツ・ライフ・ジャムゲージ・ランク、FAST/SLOWと判定誤差バー、リズムに合わせて押すだけで判定を自動調整する機能
  • YouTube動画は、キー1つでリズムだけを叩くと鍵数・難易度に合わせてレーンを自動配置するリズム譜面で遊べる。読み込んだ動画と譜面はブラウザに保存し、バックアップファイルで移行可能
  • スマートフォンでは大きな鍵盤・振動・全画面に対応。譜面・判定・スコア・保存のルールは画面から分離してテストし、GitHub Actionsでビルド・デプロイ

  • Godot 4（GDScript）で開発してWeb向けに書き出し、GitHub Actions でテスト・起動確認・Webビルド・デプロイまで自動化
  • 武器の異なる3人の主人公（木剣の2連撃、長押しで貫く弓、叩きつける棍棒）、回避（無敵）・ノックバック、被弾時のフラッシュ・ヒットストップ・画面揺れで手応えを表現
  • フックロープで杭まで飛んで水を渡り、敵を引き寄せて目を回させる操作。水中の大蛇はロープで引きずり出さないと攻撃できない
  • 全4章・9マップ（沼・雪・夜に変わる地域）、敵7種とボス4体（突進・衝撃波・扇状の弾・瞬間移動）、進行に応じて変わるセリフ、道しるべでの移動、オートセーブ
