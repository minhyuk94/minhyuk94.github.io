What I value at work

01

Communication

Development is never a solo job. It takes constant communication with planning and sales, and above all an accurate understanding of why a feature or change is being requested. Building what serves that purpose, rather than exactly what was asked, is what delivers the result that is actually needed.

02

Connectivity

I look beyond my own scope to the projects and services connected to it, and even to outside services. Noticing how another service differs from ours, or asking whether a recent security incident elsewhere could affect us too, is how I learn from those connections and prepare in advance.

03

Improvement

To me, progress is not adding new features but improving what already exists until the results are better: raising revenue, refining the UI and UX so users have an easier time, or automating workflows so the team works more efficiently. I always look for improvements that lead to outcomes like these.

WebCompiler

Browser-based tool to compile, run, judge and debug code

Why I built it Practicing coding tests in C++ or Java meant juggling compile commands and build scripts for each language, and adding and removing debug prints. I built this so I can just write code and see the result right away, and even step through it in the browser.

  • Compile and run 7 languages (C, C++, Java, Python, JavaScript, PHP, Go) from one screen
  • Compile errors with line positions; runtime errors (segfaults, exceptions, time/memory limits) with an explanation of the likely cause
  • Batch judging of test cases with a line-by-line diff of expected vs. actual output
  • Step debugger for C, C++ and Python (breakpoints, stepping, variables, call stack, watch expressions)
  • User code runs isolated: unprivileged account, resource limits, no network access
  • React

YouTuJam

A browser keyboard rhythm game where you hit falling notes to the beat. Original songs are synthesized live in the browser, YouTube music can be played too, and it works on both PC and phones

Why I built it I wanted the feel of the online rhythm games I used to play, with music I like from YouTube. Since YouTube audio cannot be analyzed, charts are generated from the tempo and first beat, or recorded by playing along.

  • 4-, 5-, 6- and 7-key modes with easy, normal and hard charts, and a level number per song calculated from note density
  • Four original songs synthesized live with Web Audio; notes are built from the song's own sounds, so each hit plays its note
  • A clock tied to the speaker's output time and judgments taken from the exact key-press time, plus hold notes, life, a jam gauge, ranks, FAST/SLOW and a timing error bar, and automatic timing calibration by tapping to a beat
  • YouTube videos are played with rhythm charts: tap the rhythm with a single key and lanes are laid out automatically for any key count and difficulty; loaded videos and charts are kept in the browser and can be moved with a backup file
  • On phones: larger keys, vibration and fullscreen. Chart, judgment, scoring and storage rules are separated from the UI and tested, with builds and deploys on GitHub Actions
  • TypeScript
  • Canvas 2D
  • Web Audio API
  • YouTube IFrame API
  • esbuild
  • GitHub Actions

Why I built it I wanted to recreate the atmosphere of the Korean online RPGs I played growing up. It is single-player for now, but the game rules are separated from the presentation so a server can be added later for multiplayer.

  • A fixed 640×480 screen with a bottom panel (chat log, HP, MP, EXP, map name and coordinates), tile-by-tile movement and front-tile attacks, and hotkey skills and items
  • Character creation (gender, hairstyle, hair color) with characters drawn from layered body, clothing, hair and weapon sprites; four jobs chosen at level 5 (swordsman, assassin, mage, monk) with 12 skills
  • Inventory, equipment, stats, skills and quest windows, shop buying and selling, portrait dialogue, a first act told through eight quests, six maps, ten monster types and two bosses
  • Stats, damage, EXP, inventory, shop and quest rules separated from JSON data and tested, including automatic checks that every NPC, exit and boss can be reached on foot on every map; music and sound effects synthesized in code

Dalmaru Adventure

A top-down action RPG built with the Godot engine: pick one of three heroes for a four-chapter adventure, with all graphics, sound and maps generated from code

Why I built it After building browser mini-games, I wanted to make a proper game with a game engine, like PC and Steam titles. This time I aimed for quality: a new story that begins in a hanok village at dusk, with combat that feels good to play.

  • Developed in Godot 4 (GDScript) and exported to the web; GitHub Actions runs tests, a launch check, the web build and deployment
  • Three heroes with different weapons (a wooden-sword combo, a bow whose held shot pierces, a club with a ground slam), an invincible dodge roll and knockback, with hit flashes, hit-stop and screen shake for impact
  • A grappling rope that flies you to posts across water and pulls enemies in to daze them; the underwater serpent boss must be dragged ashore with it before it can be hit
  • Four chapters across nine maps (swamp, snow and night regions), seven enemy types and four bosses (charges, shockwaves, fan-shaped volleys, teleporting), dialogue that changes with progress, waystone travel and auto-save
  • Pixel art (palettes, text-drawn sprites, procedural drawing, per-region recoloring), seven pentatonic music tracks and sound effects, and maps all generated from code, with automated tests that every item and exit can be reached on foot (including rope moves)
  • Godot 4
